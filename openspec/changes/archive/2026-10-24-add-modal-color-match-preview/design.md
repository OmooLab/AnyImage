## Context

现有 `MatchColorReference` 在主线程读取两张图片并一次性生成全分辨率结果。算法实测 1080p 约 0.44 秒，但连续交互还包含 Blender 像素上传、图片更新与打包，无法稳定逐帧刷新。算法已将亮度与色度调整分开，因此两个交互轴可以分别控制它们的迁移强度。

## Goals / Non-Goals

**Goals:**

- 用一次二维鼠标手势分别调节 Color 和 Lightness 迁移。
- Modal 期间只显示低分辨率临时结果，正式图片直到确认时才修改。
- 确认只产生一次 Undo；取消无损恢复所有图片、节点和材质绑定。
- 代理预览与最终结果使用同一主要颜色变换，允许省略只影响最终质量的步骤。

**Non-Goals:**

- 不追求全分辨率逐帧预览。
- 不新增侧栏、持久化调节属性或多个算法模式。
- 不维护颜色匹配原图备份或跨工具的非破坏性编辑链。
- 不改变参考 Alpha、目标 Alpha、背景处理及非 AI 执行规则。

## Decisions

### Color 与 Lightness 使用二维 Modal 手势

`invoke()` 捕获参考、目标和起始鼠标位置，Color 与 Lightness 初始均为 50%。水平位移映射到 0%–100% Color，垂直位移映射到 0%–100% Lightness；Shift 将位移灵敏度降低。当前区域使用与 Rectify 相同的居中纹理绘制方式，在预览中央显示数值，并在下方显示鼠标、确认和取消提示。

备选的 Operator 调整面板更容易实现，但需要先提交一次正式结果，且不符合直接观察结果后确认的工作流。

### 使用最长边 512 px 的代理图片

Modal 启动时从原目标生成保持宽高比的代理输入。鼠标更新只在代理尺寸执行颜色匹配，并跳过最终抖动和精细色域压缩；确认时才以相同参数运行全分辨率完整路径。预览刷新限制在约 15 Hz，防止鼠标事件积压。

备选的全分辨率缓存混合仍需在每次更新时上传整张图片，4K 图片无法保持响应；GPU Shader 预览会引入新的渲染路径和上下文差异，超出本次范围。

### 临时预览使用独立绘制层

预览创建独立 Image，并通过当前区域的 `POST_PIXEL` GPU 绘制回调居中显示，不覆盖源 Image 像素，也不替换 Image Empty、Image Texture、Material 或对象材质槽的绑定。鼠标更新只上传代理 Image；所有退出路径移除绘制回调和临时 Image。

确认时通过原有 `ImageEditTarget.commit()` 提交全分辨率结果，从而继续沿用目标有效性检查、共享数据隔离、颜色解释、命名及 Undo 行为。取消无需恢复业务数据，因为预览期间业务绑定始终未改变。

### 两个轴直接缩放各自迁移量

Color 线性缩放 OKLab 色度分布变换，Lightness 线性缩放低频亮度分位映射。100% 表示完整应用对应迁移，不叠加隐藏强度或外推；0% 保留目标图对应维度。参考色度统计适度提高有色像素权重，避免大片中性背景完全淹没主题色，但仍保持可见面积主导。最终完整路径继续执行色域压缩和确定性抖动。

### Match 处理当前 Image

预览与确认都以当前 Image 像素为输入。确认后结果直接通过图片编辑事务写回，因此连续执行会显式累积；`Set Color Reference` 同样保存当前 Image。是否在处理前复制图片由用户决定。

## Risks / Trade-offs

- [代理预览与最终像素不会完全一致] → 使用相同统计变换和参数，仅省略最终质量步骤，并保持代理长宽比。
- [绘制回调或临时图片在异常退出时泄漏] → 将两者集中由单一结束入口清理，并为确认、取消、目标失效和异常路径测试清理。
- [连续同步预览仍可能在低性能设备卡顿] → 限制最长边和刷新频率，新的移动事件始终覆盖旧参数而不排队。
- [提高有色像素权重可能放大小面积颜色] → 保留最低 35% 面积权重，只做温和强调。
