## Context

本变更覆盖审查清单的 15 项。Bake 输出通过删除 `o_image_object` 退出对象图片流程，贴图节点继续使用其独立入口。参考候选沿用 `_color`、`_normal`、`_depth` 及临时预览过滤；色板只读交互暂缓。任务按原审查编号组织，实施完成一组后核对对应行为。

## Goals / Non-Goals

目标是明确对象能力、图片写入、Scene 参考、模型安装和 Session 校验各自的生命周期，减少重复实现，并使模块、测试和内部文档对应。

本轮保留贴图节点菜单与目标解析逻辑、色板控件交互、颜色匹配算法、Bake 的共享材质与图片原位更新、现有 Shader 预览显示约定及扩展发布方式。

## Decisions

### 1. Bake 成功后撤销对象能力

在成功提交 Mesh 和清理 Modifier 后移除对象自身的 `o_image_object`，继续精确清理被消费的协议属性。菜单和对象目标识别继续读取统一标记；对象身份、变换、集合和用户属性保留。失败保持标记，Undo 恢复节点栈与标记，Redo 恢复普通 Mesh。

贴图节点入口按活动编辑树和节点判断可用性，与对象标记独立。Bake 沿用图片名称，生成贴图继续由现有参考候选规则过滤，Bake 图片写入流程无需新增参考刷新通知。

### 2. Bake 按实际图片操作校验

先检查支持的节点栈、目标对象和材质结构，再根据来源区域与法线输入确定需要执行的操作：

- 单区、无 Normal：固化几何并保留 Color 图片和采样设置，检查网格及最终 UV 所需条件。
- 多区 Color：验证被拼接与原位改写的图片及其采样、UV 假设。
- Normal 烘焙：验证法线连接、源 UV、采样方式、目标图片可写性及 Color/Normal 独立目的地。

仅被读取的输入与被写入的目标分别验证。单区 Color 的动画来源、Closest 插值等设置不因与当前操作无关而被拒绝。实际转换保持既有有效 UV 外观、退化侧壁近似、共享更新与回滚行为。

### 3. 参考数据与 Scene 同步分层

`common/color_reference.py` 提供候选参考的准备、紧凑内容身份、色板及派生数据缓存。Scene 选择、画廊枚举、派生属性同步和 load/undo/redo 回调在颜色参考属性职责内协调，由扩展入口统一注册。

公共参考数据模块和公共图片模块通过职责明确的公共接口协作，Scene 层负责同步展示。公共参考数据模块不再反向导入 Scene 属性协调层。每个 Scene 清空或替换选择时，只释放已没有其他 Scene 或活动交互使用者的参考资源；扩展注销及全局数据恢复按生命周期统一释放或重建。

### 4. 全尺寸参考快照属于交互会话

长期缓存保存参考签名、色板、权重、紧凑内容身份和有界缩略图。完整像素仅在准备或活动 Modal 校验时短期持有；取消、确认、错误和参考释放时结束其生命周期。选择多张大图后，旧参考全尺寸像素不得累计常驻。匹配开始与确认阶段仍能识别实际像素变化，draw 只读取已准备的数据。

色板属性的生成和同步继续服务于展示，当前编辑行为保留；任务只验证本轮整理没有改变控件交互。

### 5. 模型安装检查和校验分工

UI 在本地检查声明文件是否存在及大小是否符合，明确表示“已安装”；枚举和 draw 继续使用这项快速检查。服务端在首次创建 Session 前调用现有完整文件校验，利用文件身份和 checksum 缓存跳过重复计算。

校验失败以模型 key 和可读原因记录在现有模型资源状态中；UI 读取 Runtime 已有状态快照展示错误与重新下载入口。draw 不发起网络请求、服务启动或 checksum 计算。缺失文件沿用现有安装入口，同尺寸损坏文件在加载失败后也能修复。

重新下载开始时释放目标模型的 Session，沿用现有原子文件替换及 checksum 检查；成功后清理该模型的失效校验状态，再次加载使用新文件。其他模型的 Session 保持现有生命周期。校验不通过时不创建 Session，也不进入推理。

### 6. 模块和公共接口归属

- `remove_background/` 以 `operators.py` 为入口，HDR 专属输入与事务实现放入该包；`common/hdr_image.py` 保留多业务复用能力。
- 颜色匹配 Operator 按 `color_match` 命名；一个入口仍清晰时使用单文件，形成多个专属模块时以 `operators.py` 为包入口。
- Bake 的临时 Color 图片创建复用 `common/image.py` 的创建能力，写入策略继续按实际 packed 图片行为保留。共用创建和资源清理不复制第二套。
- Polygon 模块明确可跨模块调用的公共接口，Viewport 消费公共接口；测试从真实属主导入。迁移同步类型导入、注册清单和测试引用。
- `_profile_field()`、`_remove_zero_thickness()` 与无效 `models_status(refresh=...)` 参数在核对真实调用、回调和工具入口后删除。

### 7. 模型身份和档位来自目录

模型目录单独声明 `Fast/Base/Pro` 档位；Preferences、枚举和 Server Panel 从同一字段读取。加载状态使用稳定模型 key，空槽使用明确的空值。显示 label 的变化或目录排序不改变身份和档位。Blender 与服务端均从独立的 `server/model_catalog.py` 读取协议定义。

### 8. 测试与内部文档随职责整理

参考数据测试归 `tests/anyimage/common`，Scene 属性与回调测试归相应顶层属性职责，匹配交互与提交测试归 Operator。Bake 的跨文件测试辅助函数移到 `tests/support`，保留有价值的数值、事务、共享数据和 Undo 覆盖。

共享 Shader 的测试应覆盖真实创建及 framebuffer 显示编码路径；已有 GPU 验证证据先核对，再补缺少的中灰、方向和半透明边缘验证。缺少图形上下文时保留明确待验项，Mock 通过不能替代 GPU 验证。

按最终职责更新 `docs/internals` 的 Common、架构、Operator 索引、颜色匹配、Bake、去背景和产物协议。此次用户授权包含内部文档整理，实施阶段使用文档源码检查验证链接和路径。

## Risks / Trade-offs

- 公共接口迁移影响导入与注册 → 每组迁移同时更新调用者和相关测试，核对逆序注销；最终检查旧路径。
- 参考缓存缩减影响 Modal 内容变化判断 → 保留内容身份检查、连续编辑、跨 Scene 共享和 Undo/Redo 覆盖。
- 服务端首次读取大模型会增加加载时间 → 复用现有完整校验缓存，UI 保持本地快速检查。
- Bake 分支校验放宽影响烘焙假设 → 分别覆盖纯几何、多区 Color 和 Normal 三类操作，验证实际外观和失败回滚。
- 节点构建帮助函数清理影响生成资产 → 修改后运行 `uv run --group blender node-group build`，验证资产及 Capture Attribute 为零。

## Migration Plan

按 tasks.md 的编号逐组实施及核对。源码迁移一次性更新真实调用者，保持公开 Blender ID 和现有有效数据协议。当前已完成的 Bake、颜色匹配和 ONNX 变更若在本提案前归档，应先核对其最终规格；本变更以本次确认的 Bake 对象身份和按操作校验要求为准。

实施阶段运行受影响测试；跨模块整理完成后运行完整测试并确认正常退出，检查内部文档路径、旧引用和最终差异。节点构建涉及的生成资产按项目规范保留为本地产物，文档构建与扩展打包维持现有独立执行流程。
