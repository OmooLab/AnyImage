## Context

现有 `MatchColorReference` 在主线程读取两张图片并一次性生成全分辨率结果。算法实测 1080p 约 0.44 秒，但连续交互还包含 Blender 像素上传、图片更新与打包，无法稳定逐帧刷新。当前算法已将亮度与色度调整分开，因此可以增加整体迁移强度和独立的低频对比调整。

## Goals / Non-Goals

**Goals:**

- 用一次二维鼠标手势完成 Match 和 Contrast 调节。
- Modal 期间只显示低分辨率临时结果，正式图片直到确认时才修改。
- 确认只产生一次 Undo；取消无损恢复所有图片、节点和材质绑定。
- 代理预览与最终结果使用同一主要颜色变换，允许省略只影响最终质量的步骤。

**Non-Goals:**

- 不追求全分辨率逐帧预览。
- 不新增侧栏、持久化调节属性或多个算法模式。
- 不维护颜色匹配原图备份或跨工具的非破坏性编辑链。
- 不改变参考 Alpha、目标 Alpha、背景处理及非 AI 执行规则。

## Decisions

### Match 使用二维 Modal 手势

`invoke()` 捕获参考、目标和起始鼠标位置，初始值为 Match 100%、Contrast 0%。水平位移映射到 0%–150% Match，垂直位移映射到 -50%–+50% Contrast；Shift 将位移灵敏度降低。区域 Header 显示当前数值，避免为不同编辑器分别维护绘制回调。

备选的 Operator 调整面板更容易实现，但需要先提交一次正式结果，且不符合直接观察结果后确认的工作流。

### 使用最长边 512 px 的代理图片

Modal 启动时从原目标生成保持宽高比的代理输入。鼠标更新只在代理尺寸执行颜色匹配，并跳过最终抖动和精细色域压缩；确认时才以相同参数运行全分辨率完整路径。预览刷新限制在约 15 Hz，防止鼠标事件积压。

备选的全分辨率缓存混合仍需在每次更新时上传整张图片，4K 图片无法保持响应；GPU Shader 预览会引入新的渲染路径和上下文差异，超出本次范围。

### 临时预览绑定是可回滚事务

预览创建独立 Image，不覆盖源 Image 像素。Image Empty 临时改绑自身数据；对象材质目标在材质被其他对象共享时临时复制材质并只替换当前对象槽；其他 Image Texture 临时替换当前节点图片。事务记录原始绑定，确认和取消前均先恢复。仅当绑定仍由本 Modal 持有时执行恢复，避免覆盖交互期间的外部修改。

确认恢复原始绑定后，通过原有 `ImageEditTarget.commit()` 提交全分辨率结果，从而继续沿用共享数据隔离、颜色解释、命名及 Undo 行为。所有退出和异常路径删除临时 Image 与临时材质。

### Contrast 只扩展低频亮度跨度

Match 线性缩放现有完整亮度和色度调整量。Contrast 以匹配后的中间亮度为支点，仅扩大或缩小低频亮度基底偏差，再叠回原始细节；这样亮区与暗区可以分离，同时避免直接放大 JPEG 高频噪声。最终完整路径继续执行色域压缩和确定性抖动。

### Match 处理当前 Image

预览与确认都以当前 Image 像素为输入。确认后结果直接通过图片编辑事务写回，因此连续执行会显式累积；`Set Color Reference` 同样保存当前 Image。是否在处理前复制图片由用户决定。

## Risks / Trade-offs

- [代理预览与最终像素不会完全一致] → 使用相同统计变换和参数，仅省略最终质量步骤，并保持代理长宽比。
- [临时材质或图片在异常退出时泄漏] → 将预览绑定封装为单一事务，并为确认、取消、目标失效和异常路径测试清理。
- [连续同步预览仍可能在低性能设备卡顿] → 限制最长边和刷新频率，新的移动事件始终覆盖旧参数而不排队。
- [Match 超过 100% 可能越界] → 限制为 150%，最终仍经过色域压缩。
