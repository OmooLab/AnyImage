## Context

`preferences.py` 保存 storage_root，默认 `~/.anyimage`；Runtime 通过回调读取。安装由 SetupAIEnvironment 调用 BlendJob 的安装 Operator，完成后下载默认模型。当前 Preferences 直接展示目录编辑框。

本地 BlendJob 使用 `.venv`、manifest、安装状态与日志，并通过 uv 的 managed Python 创建环境。本机 `.anyimage/.venv/pyvenv.cfg` 的 home 指向用户 AppData 下的 uv Python；安装代码使用 uv 默认缓存和系统临时目录。因此迁移必须验证环境实际可运行性。位置管理的文件范围为整个 Server 根目录。

## Goals / Non-Goals

目标是让用户在下载前选择磁盘，复用有效安装，并可验证地迁移完整数据。此次交付为提案；实施范围覆盖位置管理、依赖能力核实和相关测试。

## Decisions

### 1. 选择存放目录，保存实际根目录

安装与迁移统一选择存放目录，以 Server Location 标注选择器，实际根目录固定为所选目录下的 `.anyimage`。选 `D:\` 得到 `D:\.anyimage`；选 `D:\AI` 得到 `D:\AI\.anyimage`。界面显示实际路径并探测该目录中的安装。若用户误选末级名为 `.anyimage` 的目录，提示选择其父目录并阻止确认。首次默认选择用户目录，预览其中的 `.anyimage`。现有 storage_root 值按实际目录读取，只有新选择执行上述规则。

Preferences 显示只读实际位置和安装状态。未安装显示 Set Up AI Server；环境已安装显示 Move AI Server。取消选择或确认不改配置。

### 2. 同一安装入口完成安装和指认

选择目录后以目标目录执行探测，展示“安装”“使用已有安装”或“补全安装”的结果说明，确认前展示实际路径和下载量。有效性覆盖平台、Python、依赖契约及实际解释器启动；模型缺失单独展示，复用有效模型。执行时重新探测，成功后刷新 Runtime 和模型状态并持久保存配置。识别有效安装无需联网，模型下载继续遵循 Online Access。

不存在目标时安装；已存在的无关或无法识别的非空目录报告冲突；可识别但不完整的 AnyImage 安装仅通过明确的补全动作处理。不能用“存在 .anyimage”替代校验。

### 3. 迁移与使用既有安装明确区分

Move AI Server 打开文件夹选择器，选定存放目录后直接开始迁移。空目标执行迁移；目标非空时报告冲突并要求另选目录。既有安装指认由安装入口完成。相同目录直接结束；源目标互为祖先时拒绝，路径比较考虑 Windows 大小写和链接解析。

### 4. 复制、验证、切换、清理

迁移进入独占维护状态，安装、下载和推理期间禁用入口。空闲 Server 先停止并等待退出，同时防止新任务提交；检测其他进程占用，无法保证独占则中止。后台复制整个根目录到目标盘的临时目录，展示进度；验证文件完整性及新位置环境可启动，然后提交最终目录、更新配置和 Runtime 状态，最后删除明确的旧根目录。

切换前出错或取消保留源目录和配置，清理本次临时副本。切换后的源清理失败以新目录运行，但迁移状态保持待清理并显示残留路径，支持重试。原根目录删除后才报告迁移成功。记录最小迁移阶段和源目标信息，重启后能辨别未完成复制与已切换但待清理状态；删除前再次核实路径和记录。

BlendJob 的 JobRuntime.location_controller 负责后台环境准备、目录锁、复制校验、进程退出、阶段记录与源清理。Runtime 保存 Server 进程记录，重载后以实例身份和所属 Blender 进程验证并恢复连接；Windows 强制退出时关闭受控进程树。AnyImage 负责 `.anyimage` 定位规则、默认模型准备和主线程配置保存。以原根目录删除后 Server 可启动、模型可加载和任务可执行为准。根目录内的缓存随整体迁移。

目录锁与迁移记录统一保存在用户应用数据目录，按实际安装路径的摘要区分；目标检查实际创建目录与写入文件的能力。权限不足时保留源安装及配置，并提示选择有写入权限的文件夹。迁移期间禁用 Job Server 面板与 Server 控制 Operator，取消入口在配置切换前可用。

## Risks / Trade-offs

- 跨盘复制需要目标盘容纳完整数据 → 提前估算空间，错误时保留原安装。
- 虚拟环境引用外部 Python → 验证解释器及依赖，先完成 BlendJob 重定位实验再实现迁移。
- 源目录删除失败 → 保持待清理状态并支持重试，清理完成后才报告成功。
- 目标已有数据 → 报告冲突并选择空目标。

## Migration Plan

保留现有 storage_root 配置值，替换界面入口。新增类型同步注册与逆序注销。若 BlendJob 接口变化，同步检查 wheel、锁文件、Manifest 和相关打包测试。只运行相关测试，不主动更新开发说明或构建扩展包。

## Open Questions

实施前确认 BlendJob 停止、状态重置、跨进程占用与重定位接口；用环境运行实验结论决定是否需更新本地 wheel。用户交互按上述规则实施。
